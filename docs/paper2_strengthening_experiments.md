## Experiment 126: Same-Clock Compute-Matched Organizations

Contract: `configs/sparse_same_clock_organization_control_v1.yaml`

Experiment 126 addressed the paper's largest comparability weakness under a
frozen 50-MHz, 2/12/6-lane, 180-DSP, 32-bit-AXI contract. Its independent and
rectangle organizations routed with 185 DSP48E1 cells against the exact
180-DSP gate; global used 180, but the packaging flow failed. No organization
was accepted and no matched board comparison was run. Thresholds and controls

`configs/sparse_same_clock_organization_control_postfailure_126b_v1.yaml`

## Experiment 127: Second Finite-Receptive-Field Topology

Contract: `configs/finite_receptive_field_closure_validation_v1.yaml`

The second graph is a deterministic branched residual topology:

```text
input -> 3x3 conv -> dilated 3x3 conv --+
  |                                      +-> add -> 3x3 conv -> output
  +--------------------------------------+
```

The longest support path has radius four. Eight synthetic masks cover center,
boundary, fragmented, banded, checkerboard, and dense requests. The checker:

- derives reverse closure from exact discrete supports;
- compares every node's closure with exhaustive forward support-path
  enumeration;
- independently enumerates exact input-to-requested-output support-offset paths
  and records a coordinate/edge-offset witness attaining Chebyshev radius four;
- evaluates dense and closure-only integer graphs and compares selected output;
- removes every required input position in turn and requires an output-change
  witness; and
- hashes every selected-output vector.

All preregistered software gates pass. The result is
`results/tables/finite_receptive_field_closure_validation_v1.json`, generated by
`src/hardware/validate_finite_receptive_field_closure.py` and protected by
`tests/test_validate_finite_receptive_field_closure.py`.

This result supports transfer of the closure-generation abstraction to one
second finite-support DAG. It is not RTL simulation, formal verification, a
routed design, a second trained workload, or physical generality evidence.
The completed stage needs Python only and no board or proprietary tool. A
future physical extension would first require an RTL datapath and independent
integer vectors, followed by XSim, one route, and one board capture under a new
contract; none is authorized by this result.
